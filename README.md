# 🦑 釣況紀錄

記錄每次出釣（包含槓龜）的釣獲與當下海況，依照條件分析什麼天氣比較好釣。主要釣點是東北角水湳洞一帶，以軟絲為主。手機優先，可以加到主畫面當 App 用（PWA），電腦也有專屬版面。

**正式網址：https://fishing.weather-push-worker.workers.dev**

> 沒有登入：知道網址的人都能看到並修改資料，網址不要公開分享。

## 功能

| 畫面 | 內容 |
|---|---|
| **今天（總覽）** | 一句話結論（適不適合出釣、哪些數值超標）、風／陣風／浪三個主要圓環、潮汐／氣溫／海溫／雲量／月亮／氣壓六個參考圓環、今日釣獲、一週逐時預報表（1／2／3 小時切換） |
| **行事曆** | 月曆上直接顯示每天釣到幾隻（軟絲／魚圖示），沒釣到顯示「槓龜」；點進某天可以新增或編輯出釣與釣獲 |
| **記錄釣獲** | 種類（軟絲／魚）、時間、胴長、重量、**木蝦顏色**（紅、藍、綠、紫、粉紅、灰、黃、褐色點，預設不選）、備註、**照片（從相簿選，最多 6 張，可一次選多張，點縮圖看大圖）**；當下的風浪、潮汐會自動附上 |
| **分析** | 軟絲紀錄（最大隻前 5 名，點一下打開那天的出釣；每月平均胴長／最大隻／隻數趨勢）；依區間彙總各條件下的每小時釣獲數與分數；各木蝦顏色釣到幾隻 |
| **設定** | 管理釣點（可「用目前位置」設定座標，之後自動判斷釣點）、選擇天氣資料來源、**好時段通知**開關、手動更新天氣 |

每個圓環標題旁有 **ⓘ**，滑鼠移上去（手機點一下）會顯示：這項數據是什麼、建議區間、以及你自己紀錄中表現最好的區間。

## 資料從哪裡來

| 資料 | 來源 | 更新頻率 |
|---|---|---|
| 風速、陣風、風向、氣溫、雲量、降雨、氣壓 | **溫古魯** GFS 13 km（溫古魯頁面最上面那張表），抓不到時用 **Open-Meteo** 的同一套 NOAA GFS（`gfs_seamless`） | 每 20 分鐘 |
| 浪高、週期、浪向、湧浪 | **溫古魯** GFS-Wave 16 km，抓不到時用 **Open-Meteo** 的 `ncep_gfswave016` | 每 20 分鐘 |
| 海溫 | Open-Meteo Marine（溫古魯沒有） | 每 20 分鐘 |
| **潮汐（漲／退／滿／乾）** | **中央氣象署潮汐預報**（F-A0021-001，地點「新北市瑞芳區」），沒有資料時才退回 Open-Meteo 的海面高度模型 | 預報剩不到 20 天時自動抓下一個月 |
| 月亮亮度 | 用 [`suncalc`](https://github.com/mourner/suncalc) 在本地計算，不需要 API | 即時計算 |

### 為什麼這樣搭配

- **溫古魯和 Open-Meteo 用的是同一套模型**：兩者都直接拿美國 NOAA 發布的 GFS／GFS-Wave 原始資料，溫古魯不是從 Open-Meteo 來的。指定同一套模型，補資料時數字才會一致。
- **潮汐改用氣象署**：比對後發現 Open-Meteo 的海面高度模型，早上那一波大潮準（誤差約 20 分鐘），但**傍晚那一波小潮會早 1.5–2 小時**，剛好是傍晚出釣的時段，所以改用氣象署的滿／乾潮時間。
- 溫古魯沒有公開 API，這裡用的是網頁本身呼叫的內部 API（帶 `Referer` header），個人低頻率使用。如果哪天改版抓不到，會自動改用 Open-Meteo，紀錄不會中斷。

### 天氣怎麼存

- 每 20 分鐘抓「昨天到未來 8 天」的逐小時資料，寫進 `weather_hourly`，每個釣點每個小時只有一筆。
- **已經過去的小時不會再被覆蓋**，留下的就是最接近當下的那次預報；現在和未來的小時則每次都更新成最新預報。
- 新增或修改出釣時，如果那段時間還沒有天氣資料（例如補記以前的紀錄），會用 Open-Meteo 補抓過去的資料（超過約 3 個月改用 historical-forecast-api）。
- 一個釣點一年大約 8,760 筆，D1 免費的 5 GB 夠用很久。

## 各項數據怎麼算

| 數據 | 說明 |
|---|---|
| 風速 | 10 公尺高的平均風速，畫面上用**節（kn）**顯示，跟溫古魯一樣 |
| 陣風 | GFS 模型有時給出比平均風速還小的陣風（溫古魯原始資料也有同樣狀況），這在物理上不合理，所以**寫入前若陣風 < 風速，就改成等於風速** |
| 風向、浪向箭頭 | 跟溫古魯一樣，箭頭指向風（浪）**吹去**的方向；文字是風**吹來**的方向 |
| 風向文字 | 資料庫存精確角度（例如 174°）。畫面顯示 **16 方位**（北北東、東北東…），單日紀錄另外附上角度；出釣期間的風向用向量平均（350° 和 10° 平均是 0°，不是 180°）。**分析分組用 8 方位**，避免每組樣本太少 |
| 浪高 | 示性波高（大約是最高三分之一的浪的平均） |
| 潮汐 | 用氣象署的滿／乾潮時間判斷：**滿潮或乾潮前後 40 分鐘內算平潮**（顯示「滿潮」「乾潮」），其他時間看上一個事件——上一個是乾潮就是「漲潮」，是滿潮就是「退潮」 |
| 月亮亮度 | 月面被照亮的比例，0% 新月、100% 滿月 |
| 時間 | 全部以 unix 秒存，顯示時換算成台灣時間（UTC+8） |

## 評分與分析

評分 0–100 分，**50 分是普通**。分數由兩部分混合：

| 部分 | 內容 | 權重 |
|---|---|---|
| **一般經驗** | 風浪在建議區間內、傍晚到前半夜（清晨次之、白天最差）、漲潮或滿潮前後、沒有大雨、海溫 20°C 以上會加分 | 你的紀錄越少，占比越高 |
| **你的紀錄** | 比對你過去在什麼條件下釣得比較好（見下方） | 個人時數 ÷（個人時數 + 10）：10 小時約各半、30 小時約 75% |

所以就算還沒有紀錄也能評分；記錄越多，就越貼近你自己的釣況。

**你的紀錄怎麼算**：

1. 每次出釣的時間切成一小時一格（沒釣滿一小時的按比例算）。
2. 每一格依當時的條件分組：**浪高、潮汐、月亮亮度、風向（8 方位）、風速、雲量、時段、氣溫、海溫、降雨**。
3. 每一組算「**每小時釣獲數** = 這個條件下釣到幾隻 ÷ 釣了幾小時」，跟你的整體平均比較換成分數。
4. 釣的時數很少的分組會被拉回平均值（`SMOOTHING_HOURS = 3`），避免只去過一次就變成極端分數。

**槓龜也要記**，不然分析會失真。附近共用同一個天氣來源的釣點，評分會一起使用它們的紀錄。

**「今天較好的時段」與好時段通知**：只列**評分 55 以上**、而且**風、陣風、浪都不是「不推薦」**的時段；沒有就不列、不通知。

**木蝦顏色**是每隻釣獲的屬性（同一趟可能換好幾支），只統計各顏色釣到幾隻與平均胴長，不算進每小時的條件分析。

### 跨天（夜釣）

例如星期五 21:30 釣到星期六 09:00：

- **記錄**：結束時間比開始早會自動當成隔天；釣獲時間比出釣開始早也會自動算成隔天（03:00 → 週六 03:00）。一趟最長 24 小時。
- **天氣、潮汐、分析**：照實際時間逐小時處理，跨過午夜沒有差別；時段分組會分到「前夜 19–23」「深夜 23–3」「清晨 3–7」。
- **歸屬日期**：整趟記在**開始那天**（週五），行事曆與每月統計都算在週五；週六的單日畫面也會列出這趟，標示「從前一天延續」。
- **首頁今日釣獲**：凌晨時會包含前一天開始、還在進行的那趟。

## 建議區間（紅黃綠）

圓環的顏色代表是否在建議區間內：**原本的顏色＝適合、黃色＝注意、紅色＝不推薦**。這是岸邊用餌木釣軟絲的一般經驗值，不是從你的資料算出來的，可以在 `src/lib/advice.ts` 調整。

| 項目 | 適合 | 注意 | 不推薦 |
|---|---|---|---|
| 風速 | ≤ 10 kn | 10–15 kn | > 15 kn |
| 陣風 | ≤ 15 kn | 15–20 kn | > 20 kn |
| 浪高 | ≤ 1.2 m | 1.2–1.8 m | > 1.8 m |
| 海溫 | ≥ 20 °C | 18–20 °C | < 18 °C |
| 氣壓 | ≥ 1010 hPa | 1005–1010 hPa | < 1005 hPa |

潮汐、氣溫、雲量、月亮沒有絕對的好壞，只顯示說明不變色，好不好釣看「你的紀錄」那一段。

## 好時段通知

- 每天**下午 3 點**（排程更新完天氣後）檢查接下來 24 小時，把連續的好時段合併，挑分數最高的一段通知，例如「🦑 今晚 17–23 點適合出釣｜水湳洞｜評分 59｜風 9kn・浪 0.9m・漲潮→滿潮→退潮」。
- **一天最多一則**，條件不好的日子不通知（`push_sent` 表記錄每天是否已檢查）。
- iPhone 要先「加入主畫面」，從主畫面的 App 打開才能開啟通知。
- 推播金鑰（VAPID）用 `node scripts/setup-push.mjs` 產生並直接存成 Cloudflare secret。

## 系統架構

```
手機／電腦瀏覽器（PWA）
        │
        ▼
Cloudflare Worker「fishing」 ── 提供前端靜態檔（dist/）
        │                     └─ /api/*：出釣、釣獲、照片、預報、分析
        │
        ├── D1 資料庫 fish-db ── 紀錄、天氣、潮汐、照片
        │
        └── 排程 */20 * * * * ── 溫古魯 → Open-Meteo（補缺）→ 氣象署潮汐（需要時）
```

| 部分 | 技術 |
|---|---|
| 前端 | React 19 + MUI 9 + SWR，Vite 打包；900px 以上用電腦版（`src/pc/`），以下用手機版（`src/mobile/`）。手機版整個 App 固定一個螢幕高（`100dvh`），內容區捲動、底部導覽只有圖示並接在內容下面（不用 `position: fixed`，避免 iPhone 頁面短時導覽列被推上去） |
| 後端 | Cloudflare Worker（`worker/`），同一個 Worker 也提供前端靜態檔 |
| 資料庫 | Cloudflare D1（SQLite），schema 在 `migrations/` |
| 照片 | 存在 D1 的 `photos` 表（不用 R2，免綁卡）。上傳前在手機端縮到 1600px（單張上限約 1.5 MB），另外存一張約 360px 的**縮圖**（約 10–30 KB）；清單、表單、排行榜用縮圖，點開放大才載入原圖。舊照片沒有縮圖時，App 打開會在背景自動補 |
| 共用邏輯 | `shared/conditions.ts`：時間換算、月相、潮汐判斷、分析分組、評分，前後端共用 |

## 資料庫

| 資料表 | 內容 |
|---|---|
| `spots` | 釣點：名稱、座標、溫古魯 spot id、共用哪個釣點的天氣（`weather_spot_id`）、氣象署潮汐地點、排序、是否預設 |
| `trips` | 出釣：釣點、日期、開始／結束時間、備註 |
| `catches` | 釣獲：所屬出釣、時間、種類（`squid`／`fish`）、魚名、長度（軟絲為胴長）、重量、木蝦顏色、備註、照片 key |
| `weather_hourly` | 逐小時天氣與海況，主鍵 `(spot_id, time)` |
| `tide_events` | 氣象署的滿潮／乾潮時間與潮高，主鍵 `(spot_id, time)` |
| `photos` | 照片的二進位資料 |
| `push_subscriptions` | 開啟通知的手機／瀏覽器 |
| `push_sent` | 每天是否已經檢查並通知過 |

Migration 依序是：

1. `0001_init.sql`：初始資料表
2. `0002_photos.sql`：照片改存 D1
3. `0003_spot_weather_source.sql`：釣點共用天氣與排序，新增附近釣點
4. `0004_tide_events.sql`：氣象署潮汐
5. `0005_egi_color.sql`：釣獲的木蝦顏色
6. `0006_push.sql`：好時段推播
7. `0007_catch_photos.sql`：一筆釣獲多張照片（`photo_keys`，舊資料自動搬過去）
8. `0008_photo_thumbs.sql`：照片縮圖

## 部署與設定

### 自動部署

push 到 `main` 會自動執行 `.github/workflows/deploy.yml`：

安裝 → 建置 → 檢查 secret → **套用 D1 migration** → `wrangler deploy`

失敗時，錯誤原因會寫成 GitHub Actions 的 annotation，在 Actions 頁面就看得到。

### 需要的 secret

| 放在哪裡 | 名稱 | 用途 |
|---|---|---|
| GitHub → Settings → Secrets and variables → Actions → **Repository secrets** | `CLOUDFLARE_API_TOKEN` | 部署用。權限：Workers Scripts Edit、**D1 Edit** |
| 同上 | `CLOUDFLARE_ACCOUNT_ID` | Cloudflare 帳號 ID |
| Cloudflare Worker secret | `CWA_API_KEY` | 中央氣象署開放資料金鑰，抓潮汐預報用。設定方式：`npx wrangler secret put CWA_API_KEY` |
| Cloudflare Worker secret | `VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY` | 推播金鑰，執行 `node scripts/setup-push.mjs` 自動產生並設定 |

金鑰都不放在程式碼或 repo 裡。

### 第一次建立資源（已經建好就不用）

```bash
npx wrangler d1 create fish-db        # 把 database_id 填進 wrangler.toml
pnpm db:migrate:remote
npx wrangler secret put CWA_API_KEY
pnpm deploy                           # 手動部署
```

## 本地開發

```bash
pnpm install
pnpm db:migrate:local
pnpm dev:api   # Worker 跑在 :8787（本地資料庫，跟正式環境分開）
pnpm dev       # 前端，/api 會代理到 :8787
```

- 本地資料庫在 `.wrangler/`，跟正式環境的 D1 **完全分開**，測試不會影響真實紀錄。
- 手動觸發排程：`curl "http://127.0.0.1:8787/__scheduled?cron=*/20+*+*+*+*"`，或在 App 的「設定 → 立即更新」。
- 本地沒有設定 `CWA_API_KEY` 時，潮汐會用模型備援。

## 已知限制

- **資料是附近格點的值，不是釣點正上方**：GFS 取到的格點大約在水湳洞南方 13 公里；海溫與模型潮汐的格點在東北方約 13 公里外海。數字代表區域的大致狀況。
- **潮汐預報是「新北市瑞芳區」**，跟水湳洞距離很近但不是同一點，時間可能有幾分鐘差異。
- **溫古魯沒有歷史資料**：App 上線（2026-11-24）之前或補記的紀錄，天氣都來自 Open-Meteo。2026-11-23 那筆的潮汐是用氣象署觀測站實測值回填的。
- **溫古魯內部 API 可能改版**，屆時會自動改用 Open-Meteo。
- **沒有登入**，網址不要公開。
